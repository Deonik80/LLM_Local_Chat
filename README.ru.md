## ✨ Key Features

*   **📄 Чтение локальных документов (RAG-ready):** Автоматическое извлечение текста из файлов `.pdf`, `.docx`, `.xlsx`, `.csv`, `.txt`, `.py`, `.md` с умным ограничением контекста.
*   **🖼️ Поддержка Мультимодальности (Vision):** Прикрепление изображений (`png`, `jpg`, `webp`, `gif`) с автоопределением того, поддерживает ли текущая модель зрение (с возможностью авто-фолбека на текстовый режим при HTTP 400). Вставка скриншотов прямо из буфера обмена по `Ctrl + V`.
*   **🎭 Система пресетов и профилей:** Быстрое переключение системных промптов (Переводчик, Код-ревью и др.). Создание полноценных профилей, связывающих конкретную модель, промпт, температуру, `seed` и `context_length` в один клик.
*   **📦 Загрузка окружения проекта:** Возможность подгрузить файлы `requirements.txt` и `.env` прямо в системный контекст модели для точечной разработки. Секреты (переменные с `KEY` / `TOKEN` / `SECRET` / `PASSWORD` и т.п. в имени) маскируются как `***` и не попадают в модель.
*   **🔄 Управление генерацией:** Потоковый вывод (Streaming) с троттлингом для плавности, кнопка немедленной остановки (Stop). Видимый статус генерации (`Модель думает…` → `Модель печатает…`) в пузыре и строке статуса. Прерванный ответ дописывается кнопкой **«Продолжить»**; от любого сообщения можно начать **ветку заново** (отброшенный хвост сохраняется в Variants). Своё отправленное сообщение можно **отредактировать и переотправить** — старые ответы уходят в Variants нового. Поддержка перегенерации ответов и хранения альтернативных вариантов (Variants).
*   **📈 Контроль токенов и сжатие:** Наглядный прогресс-бар заполнения контекста. Под каждым ответом — его цена (`⚡ N tok · X tok/s · Ys`). Функция автоматического или ручного сжатия истории диалога (Summarization) при переполнении лимитов. `Context Length` — ползунок, максимум подтягивается с загруженной модели.
*   **📌 Сайдбар: папки, пины и превью:** Закрепление важных чатов сверху; чаты можно разложить по **папкам** (чипы-фильтры «Все + папки» под поиском, назначение — кнопка-папка у каждого чата, поле `folder` в `index.json`). У каждого чата — превью последнего сообщения и счётчик. Модель фоном придумывает короткое название новым чатам (ручное переименование не затирается).
*   **🔍 Поиск:** Полнотекстовый поиск внутри текущего чата (`Ctrl + F`) и **глобальный поиск по всем чатам** (`Ctrl + Shift + F` или меню «⋯») — по заголовкам и телам сообщений; клик по результату открывает чат сразу с фильтром.
*   **🗣️ Голосовой интерфейс:** Голосовой ввод сообщений (STT) с красной индикацией записи на кнопке микрофона, озвучка ответов ассистента (TTS: `edge-tts` онлайн или `pyttsx3` офлайн, воспроизведение внутри приложения, длинные ответы синтезируются чанками с прогрессом) и hands-free режим диалога (слушаю → отвечаю → озвучиваю, по кругу).
*   **🖥️ Работа с сервером:** При старте программа подхватывает уже загруженную на сервере модель вместо загрузки второй; фоновая проверка здоровья сервера (красно-зелёная точка) с перезапуском в один клик через `lms`. Для сервера с включённым Authentication API в настройках появился выпадающий список **«Режим доступа к серверу»** (`Без авторизации` / `API Key`) и поле ключа с маскированием: ключ уходит в каждом запросе как `Authorization: Bearer <key>`, хранится в `data/settings.json` и не попадает ни в логи, ни в контекст модели. Ответ `401` / `403` показывается понятной локализованной ошибкой, а не сырым HTTP-дампом.
*   **🔌 MCP-серверы (mcp.json):** Необязательный режим MCP вызывает инструменты серверов MCP, уже настроенных в LM Studio: включите тумблер в настройках и выберите их метки, и приложение переключится на OpenAI-совместимый `POST /v1/responses` (у `/v1/chat/completions` поддержки MCP нет) с блоком `tools` типа `mcp`, используя тот же API-ключ как credential `Authorization: Bearer`. Вызовы инструментов видны компактной строкой прямо в чате, сам ответ остаётся чистым, а запрос stateless: в `input` уходит вся локальная история (включая ассистентские реплики). Требуется включённая настройка «Remote MCP» в LM Studio (Developer → Settings), чтобы серверы из mcp.json можно было вызывать.
*   **📦 Контроль зависимостей:** При старте программа проверяет `pypdf` / `python-docx` / `openpyxl` / `pillow` и сообщает, чего не хватает (без автоустановки в рантайме — окружение не мутируется); `run_app.bat` выполняет `pip install -r requirements.txt`.
*   **📊 Оценка ответов и экспорт:** Выставление оценок сообщениям (Feedback loop) с экспортом логов в формат `JSONL` для последующего fine-tuning. Экспорт диалогов (целиком или только отмеченные галочкой) в `Markdown`, `HTML` и `JSON`.
*   **🌐 Локализация и Темы:** Полная поддержка русского и английского языков (все строки вынесены в `locales/ru.json` и `locales/en.json` — новый язык добавляется файлом), ошибки голосового режима тоже переводятся. Адаптивная Темная и Светлая темы оформления.
*   **🧹 Чистый выход:** Автоматически выгружает модель из памяти LM Studio при закрытии приложения для экономии ресурсов видеокарты.

## 🚀 Быстрый старт

Через bat файл run_app.bat (запускает сервер LM Studio и запускает чат)

### Требования

Перед запуском убедитесь, что у вас установлены:
1.  **Python 3.9 или выше**
2.  Запущенный сервер **LM Studio** (по умолчанию ожидается адрес `http://localhost:1234/v1`). Запуск через run_app.bat запускает сервер LM Studio автоматом и запускает чат

### Установка зависимостей

Склонируйте репозиторий и установите базовые пакеты, а также модули для обработки документов и голоса:

```bash
git clone https://github.com/Deonik80/LLM_Local_Chat.git
cd LLM_Local_Chat

# Все зависимости сразу (рекомендуется)
pip install -r requirements.txt

# Или вручную:
# Базовые зависимости
pip install "flet==0.86.5" httpx pydantic pillow

# Для чтения документов PDF, Word, Excel
pip install pypdf python-docx openpyxl

# Для голосового ввода и озвучки (опционально)
pip install edge-tts pyttsx3 pygame SpeechRecognition PyAudio
```
*(Примечание: Название версии Flet в коде жестко зафиксировано под архитектуру 0.86.5. Если хелперы (`pypdf`, `python-docx`, `openpyxl`, `pillow`) не установлены, приложение стартует и подсказывает команду установки — автоустановка в рантайме не выполняется.)*

### Переменные окружения (Опционально)

Вы можете переопределить настройки по умолчанию с помощью переменных среды или файла `.env`:
*   `LM_STUDIO_URL` — базовый адрес API (дефолт: `http://localhost:1234/v1`).
*   `LM_STUDIO_AUTH_MODE` — режим доступа к серверу по умолчанию: `none` (без заголовка `Authorization`, так по умолчанию) или `api_key`. Перекрывается `data/settings.json`, как только режим сменён в UI.
*   `LM_STUDIO_API_KEY` — запасной API-ключ для режима `api_key` (уходит как `Authorization: Bearer <key>`). Перекрывается `data/settings.json`; в логи не пишется и модели не передаётся.
*   `LM_STUDIO_MCP_ENABLED` — тумблер MCP по умолчанию: `on` / `1` / `true` включает MCP, любое другое значение (включая отсутствие) оставляет обычный путь `/v1/chat/completions`. Перекрывается `data/settings.json`.
*   `LM_STUDIO_MCP_SERVERS` — запасной список меток серверов из `mcp.json`, например `playwright, brave-search` (хранятся как `mcp/<label>`, в payload `/v1/responses` уходят как `server_label` без префикса).
*   `DEFAULT_MODEL` — модель по умолчанию.
*   `REQUEST_TIMEOUT` — таймаут запросов в секундах (дефолт: `180`).
*   `CONTEXT_LENGTH` — размер контекста по умолчанию (дефолт: `8192`).
*   `MAX_IMAGE_MB` / `MAX_TEXT_MB` — лимиты на размер вложений.
*   `LOG_LEVEL` / `LOG_KEEP` — детальность логов и сколько файликов логов хранить (дефолт: `INFO` / `20`).

### Запуск приложения

```bash
python.exe app.py
```
Либо через bat файл run_app.bat

## 📂 Структура данных приложения

После первого запуска приложение создаст в корневой папке директорию `data/` со следующей структурой:
*   `data/chats/` — история сообщений в формате JSON (на каждый чат свой файл).
*   `data/attachments/` — копии прикреплённых файлов.
*   `data/tts/` — временные аудиофайлы озвучки (чистятся автоматически).
*   `data/logs/` — отдельный лог на каждый запуск (`app-YYYYMMDD-HHMMSS.log`, хранятся свежие 20, меняется через `LOG_KEEP`).
*   `data/index.json` — глобальный список чатов для сайдбара: название, закрепление, папка, превью последнего сообщения и счётчик сообщений.
*   `data/settings.json` — конфигурация UI, темы, языка, последних параметров слайдеров, режим доступа к серверу с его API-ключом (`auth_mode` / `api_key`) и тумблер MCP с выбранными серверами из `mcp.json` (`mcp_enabled` / `mcp_servers`).
*   `data/presets.json` — пользовательские системные промпты.
*   `data/profiles.json` — ваши сохраненные профили связок.

Запись всех JSON-файлов атомарная (временник + переименование, на Windows — с ретраями, если файл занят): сбой посередине не оставляет полузаписанный файл, а нечитаемый JSON сохраняется рядом как `*.corrupt` для ручного восстановления. Временные `*.tmp` не накапливаются.

> **⚠️ API-ключ хранится открытым текстом.** В режиме доступа `api_key` токен пишется в `data/settings.json` как есть — без шифрования, без системного хранилища ключей и без обфускации, поэтому любой, кто прочитает этот файл (или его резервную копию), получает ключ. Приложение никогда не отдаёт ключ модели и не пишет его в логи, а `.gitignore` исключает `data/settings.json`, чтобы файл случайно не попал в коммит. Считайте файл секретом: не кладите его в общие папки, в папки облачной синхронизации, которую вы не контролируете, и в историю репозитория. `LM_STUDIO_API_KEY` — запасной вариант только для первого запуска: как только настройки сохранены из интерфейса, значение из файла главнее.

## 🔌 MCP-серверы (mcp.json)

Приложение умеет вызывать инструменты MCP-серверов, уже настроенных в LM Studio (`mcp.json`). Включите **Настройки → MCP-серверы → Использовать MCP-серверы сервера** и введите метки серверов в поле рядом (они появятся чипами с крестиком — это ключи из вашего `mcp.json`). Приложение переключится на OpenAI-совместимый `POST /v1/responses` (у `/v1/chat/completions` поддержки MCP нет) и будет слать блок `tools` типа `mcp` с метками серверов в форме `server_label` — без префикса `mcp/`. Если тумблер выключен, ничего не меняется: запросы, локальная история и разбор ответа остаются ровно как раньше.

Требования и поведение:
*   **LM Studio 0.4.0 или новее** — MCP через API живёт в нативном v1 REST API. Если такого эндпоинта нет, приложение сообщает об этом отдельным текстом, а не сырым HTTP-дампом.
*   В настройках сервера LM Studio включите **«Allow calling servers from mcp.json»**. Если сервер отклонит вызов из-за этой настройки, приложение скажет об этом прямо.
*   Режим доступа `api_key` работает и как credential для MCP: серверы из `mcp.json` вызываются с тем же заголовком `Authorization: Bearer <API token>`, поэтому при включённой авторизации задайте API-токен в **Настройки → Доступ к серверу**. На `401` / `403` показываются те же локализованные сообщения о доступе.
*   **Эндпоинта, перечисляющего настроенные MCP-серверы, у LM Studio нет**, поэтому метки вводятся руками — это ключи (`server_label`) из вашего `mcp.json`; выбранные серверы хранятся списком в `data/settings.json` (`mcp_enabled` / `mcp_servers`).
*   Payload инструментов — форма `server_label`, проверенная на живом LM Studio 0.4.x: это единственная принимаемая сервером форма. `integrations: ["mcp/<id>"]` отвечает `200`, но инструменты не подключает (молчаливый no-op), а `tools: [{"type": "mcp", "id": "mcp/<id>"}]` отклоняется с `400` “Invalid input”. Приложение показывает каждый вызов инструмента компактной строкой прямо в чате — `⚙ инструмент(аргументы)`, затем `⚙ инструмент → результат` или `⚙ инструмент ✗ ошибка` — а финальный текст стримит как обычно. Вывод инструментов в ответ не попадает; если модель только вызвала инструменты и не вернула текст, в ответе показывается короткая пометка вместо пустого пузыря.
*   В режиме MCP используется stateless `POST /v1/responses`: вся локальная история (включая ассистентские реплики и картинки) уходит в `input` в каждом запросе, поэтому правка сообщения, ветвление, перегенерация, сжатие истории и смена модели работают ровно как в обычном режиме — серверной цепочки, которую можно было бы оборвать, нет. Запрос несёт блок `tools` типа `mcp` с метками выбранных серверов из mcp.json; чтобы сервер разрешал такие вызовы, включите «Remote MCP» в LM Studio (Developer → Settings). Заголовки чатов и сжатие истории всегда идут без MCP.
*   При выключенном MCP ничего не меняется: обычный OpenAI-совместимый путь, локальная история и `seed` как раньше.

## ⌨️ Горячие клавиши

*   `Ctrl + Enter` — Быстрая отправка сообщения из текстового поля.
*   `Shift + Enter` — Перенос строки в поле ввода.
*   `Ctrl + K` — Создать новый пустой чат.
*   `Ctrl + F` — Открыть окно полнотекстового поиска внутри текущего диалога.
*   `Ctrl + Shift + F` — Глобальный поиск по всем чатам (заголовки и сообщения).
*   `Ctrl + V` — Вставить картинку из буфера обмена как вложение.
*   `Escape` — Прервать текущую генерацию ответа (Стоп).

## 🛠 Разработка

Тесты, линтер, типы и покрытие — те же команды, что запускает CI (GitHub Actions, Python 3.9–3.13):

```bash
pip install -r requirements-dev.txt   # pytest + ruff + mypy + pytest-cov
python -m pytest                      # юнит-тесты чистых модулей
python -m ruff check .                # линтер
python -m mypy                        # типы (chat_store, repositories, fsutil, api_payload, voice, models, lm_client)
python -m pytest --cov --cov-report=term --cov-fail-under=75   # покрытие (рatchet: порог поднимается, не опускается)
```

Конфигурация линтера/типов/тестов/покрытия — в `pyproject.toml`, workflow CI — в `.github/workflows/ci.yml`. Порог покрытия — ретрайт: текущее измеренное значение (75%+) не может упасть, новые тесты поднимают его дальше.
